## Как сверено (22.11.2026)

Источник: официальная документация guide.kaspi.kz/partner/ru/shop/api (разделы «Общие вопросы», «Заказы», «Товары»). Страницы отрисовываются скриптом: ответы на вопросы подгружаются в страницу в виде данных. Текст вынут из отрисованной страницы в headless Chromium (раскрытие всех вопросов и разбор данных страницы). Извлечено 34 пары «вопрос — ответ». Сохранённые файлы — в рабочей папке сессии, в git не попали.

### Статусы заказов (`STATE_MAP`)

- Совпадают с документацией: `ACCEPTED_BY_MERCHANT` → принят → `in_progress`; `COMPLETED` → завершён → `completed`; `CANCELLED` → отменён → `cancelled`; `RETURNED` → возвращён → `returned`.
- Переходные состояния, попадают в `in_progress` по умолчанию: `CANCELLING` (в процессе отмены), `KASPI_DELIVERY_RETURN_REQUESTED` (ожидает возврата), `APPROVED_BY_BANK`. Когда они перейдут в конечный статус, синхронизация его обновит (сохранено правило перекрытия окна 14 дней).
- Есть в нашей таблице, но **в документации не встречаются**: `DELIVERED`, `CANCELED`. Оставлены как безвредные: на данные не влияют, пока Kaspi их не отдаёт.

## Что ещё не подтверждено документацией

- **Лимиты запросов и коды ошибок**: в прочитанных разделах не найдены. Наши значения (не чаще одного запроса в 0,25 с; повтор при 429 и 5xx) — осторожное допущение.
- **Формат ответа заказов** (JSON:API, `data` → `attributes` → `entries`): структура подтверждена только по форме параметров; полные примеры ответов в прочитанных данных не разобраны. Поля `offerCode`, `quantity`, `basePrice` — допущение.
- **Частичные возвраты**: в документации их нет. Возврат по позициям не моделируется.
- **XML-прайс — наличие**: без `<availabilities>` Kaspi не получает остаток. Нужен код склада из кабинета (`storeId`). Satti остатки ведёт (склад, К-1), но передавать их без кода склада нельзя. Блокер для владельца.
- **Частичная отмена**: в документации есть метод `PUT …/orderPartialCancel/{orderId}` (фрагмент из поиска, страница при загрузке дала ошибку). Количество в позиции может уменьшиться после первой синхронизации: это влияет на прибыль и склад. Не реализовано; решение владельца: учитывать или нет.
- **Снятие с продажи через XML**: официально не описано. Сторонние интеграторы пишут, что товар, которого нет в файле, Kaspi может снять. Проверить до включения.
