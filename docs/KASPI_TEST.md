# Тест подключения Kaspi на реальном магазине (инструкция, 22.11.2026)

Цель: проверить на токене знакомого продавца, что заказы, товары, категории и прайс загружаются верно, без риска для его магазина.
Перед тестом прочитайте `docs/kaspi-assumptions.md` (что сверено с документацией и что нет).

## 1. Что нужно
- Ноутбук с сервером Satti и приложением (сеть — только частная: точка доступа телефона или домашний Wi‑Fi). Интернет на ноутбуке не открывать.
- Знакомый продавец с магазином на Kaspi, который письменно согласен на тест. Его токен и ID используются только в этом тесте.
- Аккаунт в приложении Satti, не демо-аккаунт: демо не подключает Kaspi.

## 2. Включить Kaspi на локальном сервере
1. В `server/.env` (не в git): `KASPI_ENABLED=1` и `SATTI_KASPI_KEY=<ключ шифрования>` (сгенерировать так же, как ключ бэкапов; без ключа сервер не стартует при включённом флаге).
2. Перезапустить сервер.
3. В админке (раздел «Флаги») включить `kaspi_connection`. Одного `KASPI_ENABLED` недостаточно: нужны оба (тест `test_admin_flag_alone_is_not_enough`).

## 3. Войти в приложение
- Вход по почте (код на почту) под отдельным тестовым аккаунтом. Не демо.
- Создать магазин (или выбрать свой тестовый). Не использовать магазин продавца для ввода своих данных.

## 4. Подключить магазин
1. Профиль → «Подключение Kaspi».
2. Продавец в своём кабинете Kaspi Pay: Настройки → Токен API → «Сформировать» (создаёт руководитель). Ключ передаётся только на время теста и затем удаляется (п. 8).
3. ID продавца — из кабинета продавца (Настройки магазина).
4. Ввести ID и токен, нажать «Подключить». Сервер проверяет токен запросом к Kaspi.

## 5. Что загрузится
- Первая загрузка — заказы за последние 90 дней. При работающем планировщике (SATTI_SCHEDULER=1) она ставится в очередь и идёт в фоне: 10 минут – час. При 1000 заказов ~2600 запросов к Kaspi.
- Дальше — каждые 15 минут за флагом планировщика.
- Каждую ночь в 03:00 по Алматы — перечитывание заказов за 60 дней (поздние возвраты и частичные отмены).
- Позиции заказа (отдельным запросом по каждому заказу), артикул и название товара через связи товара, категория из позиции.
- Состав заказов за 14 дней и все незавершённые перечитываются при каждой синхронизации.
- Состав заказа меняется при частичной отмене: количество обновляется, в журнале склада — движение «отмена».

## 6. Что продавец вводит сам (в приложении Satti, не в Kaspi)
- Прайс-лист из кабинета Kaspi: Товары → Выгрузка прайс-листа → скачать XML → в приложении «Загрузить прайс-лист (XML)». Без него ссылку на прайс не показываем. Наш файл содержит весь каталог продавца с его ценами; меняются только наличие и остатки по складам.
- Себестоимость товаров (без неё прибыль по товару не считается).
- Остатки на складе (приход, инвентаризация).
- Налог, если нужен.
- Код склада Kaspi (storeId) — из кабинета «Склады и магазины». Без него наличие не передаётся в Kaspi.
- Ссылку на прайс вставлять в кабинет Kaspi только после проверки файла на тестовом товаре.

## 7. Проверки во время теста
- Число заказов в приложении совпадает с кабинетом продавца за тот же период.
- Выручка и прибыль за день совпадают с ручным подсчётом по 2–3 заказам.
- Категория товара не «Без категории»; у товаров без ставки комиссии в карточке написано «уточнить комиссию».
- Название товара — настоящее, не артикул.
- Частичная отмена в кабинете (если есть) отражается после следующей синхронизации.
- Ошибка «токен не принят» → статус в приложении, без повторов.

## 8. Отключиться и удалить данные после теста
1. Приложение: «Подключение Kaspi» → «Отключить». Токен и адрес прайса удаляются сразу.
2. Загруженный прайс и заказы остаются до удаления. Удалить: удаление магазина (удаляет и подключение, и загруженный прайс) или удаление аккаунта.
3. Ключ токена у продавца: в кабинете Kaspi сбросить («Сформировать» заново) — старый токен перестанет работать.
4. Записать в REPORT: дата, число заказов, найденные расхождения.

## 9. Что не проверено до теста (см. kaspi-assumptions.md)
- Лимиты запросов и коды ошибок Kaspi — в документации не найдены.
- Формат ответов связей товара (`orderentries/{id}/product`, `masterproducts/{id}/merchantProduct`) — по связям, полный пример не разобран. На тесте записать ответы (без токена) и сверить.
- Снятие с продажи через `available="no"` — официально описан только атрибут.
