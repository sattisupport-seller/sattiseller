# ADR 0012 — Покупки в App Store и Google Play, пробный период на телефон и магазин Kaspi

Дата: 23.11.2026. Основание: MASTER_PLAN 3.1–3.2; К-21 (решения владельца 23.11.2026, 01:17–01:53).

## Решение

1. **Библиотека в приложении — `expo-iap`** (StoreKit 2 и Google Play Billing, модуль Expo, работает в dev build).
   Загружается лениво (`src/lib/purchases.ts`): в Expo Go нативного модуля нет, экран показывает понятный текст и не падает.
2. **Доступ выдаёт только сервер.** Приложение присылает `transactionId` (Apple) или `purchaseToken` (Google) в
   `POST /v1/shops/{id}/subscription/verify`; сервер спрашивает магазин (App Store Server API — Get All Subscription
   Statuses; Google Play Developer API — `purchases.subscriptionsv2.get`) своим ключом по TLS и по ответу меняет подписку.
   Транзакция в приложении закрывается (`finishTransaction`) только после ответа сервера. Google-покупка подтверждается
   сервером (`acknowledge`): без этого Google вернёт деньги через 3 дня.
3. **Подписи JWS от Apple сервер не проверяет по цепочке сертификатов.** Данные, по которым выдаётся доступ, сервер
   получает сам от Apple по TLS; уведомления используются только как сигнал «перечитать состояние». Поддельное
   уведомление вызывает лишь лишний запрос к Apple. Проверку цепочки x5c (корневой сертификат Apple G3) можно добавить
   позже как дополнительную защиту — она не меняет модель доступа.
4. **Уведомления магазинов** — `POST /v1/store/apple/notifications` (App Store Server Notifications V2) и
   `POST /v1/store/google/rtdn?token=…` (Pub/Sub push; секрет в адресе). Повтор не обрабатывается дважды:
   `store_notifications` с уникальным `(store, event_id)` (notificationUUID / messageId). Продление, отмена
   (доступ до конца периода), возврат денег (доступ закрывается сразу), льготный период (доступ до его конца),
   неудачное списание (доступа нет).
5. **Покупка привязана к магазину Satti**: `appAccountToken` (Apple) и `obfuscatedAccountId` (Google) — UUID из id
   магазина и секрета сервера. Чужую покупку к своему магазину не привязать (`409 purchase_other_account`); одна
   покупка — один магазин (`store_purchases`, уникальный ключ покупки). Подписка работает на всех устройствах того же
   аккаунта Apple или Google — телефон ограничивает только пробный период (Apple 3.1.2(a)).
6. **Пробный период** (решения владельца 01:31, 01:39, 01:46): только после подключения своего магазина Kaspi;
   один на телефон, один на магазин Kaspi (ID продавца) и один на аккаунт — навсегда.
   - Телефон: iPhone — Apple DeviceCheck (два бита у Apple; локальный модуль `mobile/modules/satti-device-check`);
     Android — Play Integrity, device recall (`@expo/app-integrity`). Идентификатор телефона сервер не получает.
   - Сервер решает, что предложить (`POST /subscription/offer`): App Store — продукт с вводным предложением или продукт
     той же группы без него; Google Play — предложение `trial14` или базовый план.
   - Если магазин всё же дал пробный период (новый Apple ID), а по правилам Satti он уже был, состояние —
     `trial_denied`: доступ откроется с первой оплаты.
   - Проверка телефона недоступна (Expo Go, эмулятор, нет ключей, сбой) — пробный период не даётся, причина в журнале.
   - Отметки (хеши с секретом сервера в `billing_marks`; биты у Apple и Google) удаление аккаунта не снимает.

## Ограничения (честно)

- Всё проверено на записанных ответах в формате документации (`server/tests/test_store_billing.py`); реальные ответы
  магазинов — после аккаунтов (OWNER_TODO 7 и 10).
- Формат Play Integrity device recall (бета) взят из документации — сверить при включении.
- Модуль DeviceCheck на Swift не собирался (нет Mac); `expo-iap` в сборке не проверялся (нет dev build).
