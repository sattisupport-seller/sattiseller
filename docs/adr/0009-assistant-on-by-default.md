# ADR 0009. Помощник включён по умолчанию для беты; требования магазинов; склад

Дата: 22.11.2026. Статус: принято владельцем. Заменяет «помощник выключен на запуске» из ADR 0007 и ADR 0008.

## Решения владельца (22.11.2026)

1. **Включение.** Помощник включён по умолчанию (флаг `ai_assistant` = True в коде и `FLAG_DEFAULTS`). Выключатель в админке главнее: значение из базы перекрывает умолчание. Тесты живой модели выключены принудительно (`conftest`), платные вызовы — только в тестах с фикстурой `live`. Локальный сервер: `SATTI_AI_LIVE=1` в `server/.env`. На развёртывании — ключ и `SATTI_AI_LIVE=1` (см. `docs/OWNER_TODO.md`).
2. **Apple 5.1.2(i).** Экран согласия перед первым вопросом: данные, получатель (Anthropic, США), «Разрешить» / «Не сейчас»; без согласия помощник не работает, остальное приложение работает; отзыв — в профиле. Текст — черновик, на одобрении владельца. Предложения к политике — `docs/legal-proposals.md` (юридические тексты не менялись).
3. **Google Play.** Под каждым ответом — «Пожаловаться» (тот же механизм оценки `flag`); жалобы и 👎 — списком в админке (`GET /v1/admin/ai-feedback`, раздел «Жалобы и 👎»).
4. **Ошибки H2 общими правилами.**
   - Период распознаётся кодом (ru, kk, транслит): `resolve_period`. Период передаётся модели строкой «(Период вопроса: …)», поэтому понятный период не уточняется. Тесты: `test_period_and_rebuild.py`.
   - Неверный живой ответ (подстановка без вызова инструментов, неверные числа) пересобирается из данных инструментов; текст сбоя пользователю не уходит, если пересборка возможна. Тесты: `test_period_and_rebuild.py`, обновлён `test_ai_numbers.py`.
5. **Проверка чисел H2 без API.** 514 упоминаний: все верны по метрике, названной рядом, после ручной сверки несовпадений. Неверных — 0. Подмены метрики не найдено, поэтому новая проверка в код не добавлялась. Скрипты — `docs/eval/h2_number_check/`.
6. **Регрессия и финал.** После правок (лимит инструментов 6, период, пересборка, склад):
   - E+F: ответы 90/92 (98 %), отказы 33/33, ложные отказы 0/23, контакты 0.
   - G: ответы 43/45 (96 %), отказы 16/16, ложные 0/11.
   - H2: ответы 52/52 (100 %), отказы 18/18, ложные 0/12.
   - **H (резервный слепой набор, три прогона): ответы 42/44, 42/44, 41/44 (среднее 94,7 %), отказы 16/16 в каждом, ложные отказы 0, контакты 0. Критерий выполнен.** Набор H был открыт запуском; новых наборов не делаем.
7. **Стоимость вопроса.** Прежний учёт не считал токены кэша (системная инструкция и инструменты, около 4 000 токенов, читаются из кэша). Исправлено: запись ×1,25, чтение ×0,1 от цены входа. Фактически по всем 436 строкам регрессии: **около $0,00039 на живой ответ** (вместо прежних $0,00026). Потрачено на регрессию и проверки в этой серии — около $0,16 из запрошенного бюджета $1.

## Склад (PROPOSALS, пункт 18 — реализовано)

- Остаток = внесённый на момент инвентаризации − продажи после него (отмены не считаются) + возвраты годного товара после него. Расчёт по заказам, без фоновых задач (`app/stock.py`).
- Приход: прибавляется к текущему остатку (`POST …/stock/receipt`).
- Уведомления при понижении до 10, 5, 3 шт. и 0 — в приложении (`GET …/stock/alerts`) и push на моке (файл в `outbox/push`), один раз на порог.
- «Закончится через N дней»: прогноз по средним продажам за 14 дней; в списке, если ≤ 14 дней.
- При нуле — снятие с продажи только после подтверждения (`POST …/stock/delist` с `confirm: true`); снятые товары исключаются из XML-прайса.
- Помощник: инструменты `get_stock` и `get_stock_alerts` (только чтение) — отвечает про остатки и «что скоро закончится».
- Экран в приложении — «Склад» (из профиля): ввод остатка, приход, снятие с продажи с подтверждением.
- Не сделано: автосписание по реальным заказам Kaspi (сейчас по данным заказов магазина в базе), историческая инвентаризация, редактирование истории прихода.
