# ADR-0003. Решения ТЗ 2.1 для задачи 16

Статус: принято, 2026-11-20. Дополняет ADR-0002. Источник: `docs/spec-2.1.md`, раздел 2.2 и задача 16.

## Контекст

В ADR-0002 было записано, что `lucide-react-native` ставился с `--legacy-peer-deps` из-за конфликта peer-зависимостей Expo (react-dom 19.3.1 против react 19.3.0). ТЗ 2.1 требует убрать этот флаг.

## Проверка (2026-11-20)

- `npm install --dry-run` в `mobile/` без флага: без ошибок, «up to date».
- `npm ls`: нет `invalid`, `missing` и `UNMET`.
- `npx expo install --check`: «Dependencies are up to date».
- `npx expo-doctor`: 20/20 проверок пройдено.

Вывод: флаг `--legacy-peer-deps` больше не нужен, исключений в зависимостях нет.

## Решения

1. `--legacy-peer-deps` не используется. Установка и проверки — только обычными командами `npm install`, `npx expo install --check`, `npx expo-doctor`.
2. Типы API: цель — генерация из OpenAPI (правило CLAUDE.md, раздел «Версия 2.1»). Текущее состояние: сервер отдаёт модели ответов только у одного из 25 эндпоинтов (`/app/config`), поэтому генерация пока невозможна. Ручные типы в `mobile/src/api/types.ts` остаются до отдельного шага: добавить модели ответов на сервере, сгенерировать клиент, добавить тест на совпадение. Шаг отмечен в `docs/progress-2.1.md`.
3. Git: локальные коммиты в `feature/bootstrap`. Remote не настроен, push ждёт аккаунт GitHub (spec-2.1, шаг 19.1).

## Последствия

- Установка зависимостей проще и безопаснее: конфликты видны сразу, а не скрываются флагом.
- Типы API пока ручные; это явное отставание от правила ТЗ 2.1, отслеживается в прогрессе.
