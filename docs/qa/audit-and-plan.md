# QA: аудит и план тестирования (этапы 1–2)

Дата: 2026-11-21. Объект: ветка `feature/bootstrap`, код до этого аудита не менялся.
Тестовая среда: только локальная. Тестовые данные — временная база SQLite и тестовые адреса. Производственных данных и серверов не касались.

## 1. Архитектура и технологии

| Слой | Технология | Где |
|---|---|---|
| Мобильное приложение | Expo SDK 58, React Native 0.88, Expo Router, TypeScript strict, React Query | `mobile/` |
| Веб-версия приложения (для проверки в браузере) | react-native-web | `mobile/` |

## 2. Список функций и сценариев

**Вход и аккаунт:** вход по коду (dev), вход Apple и Google (токен), выход, обновление сессии, подтверждение возраста 18+, удаление аккаунта (в приложении и через веб-форму), демо-сессия.

**Магазин и данные:** создание магазина, обзор (KPI, серия по дням, внимание), лесенка прибыли, список товаров с фильтрами, сортировкой и поиском, карточка товара, версии закупочных цен, список заказов с фильтрами и курсором, карточка заказа, комиссии, расходы на рекламу, налоговая ставка с историей, импорт XLSX/CSV (загрузка, сопоставление, проверка, применение, отмена, файл ошибок).

**Расчёты:** прибыль строки и заказа, возвраты, налог продажи и возврата, покрытие данными, маржа, разложение изменения прибыли, золотой набор G001–G010 и R001–R004.

**ИИ-помощник:** вопросы (лимит 30 в день), черновики описаний (без новых чисел), ответы покупателю, согласие, маскировка персональных данных.

**Выгрузки:** отчёт о прибыли в Excel, «Скачать мои данные» (ZIP, 3 в сутки).

**Подписка:** состояния, пробный период (аккаунт и магазин), экран оплаты (заглушка), экран блокировки, хранение 0/60/83/90 дней.

**Админка:** статистика, флаги, блокировка пользователя, доступ поддержки на 24 часа, ошибки.

**Публичное:** `/privacy`, `/terms`, `/delete-account`, `/admin`.

## 3. Места повышенного риска (предварительно, проверяются тестами)

| № | Участок | Почему рискованно | Как проверяем |
|---|---|---|---|
| R1 | `shop_for` и все эндпоинты с `shop_id` | разграничение прав между аккаунтами | тесты «чужой магазин» по всем маршрутам с `shop_id` |
| R2 | параметры запроса: `period`, `status`, `q`, `cursor`, `sort`, `filter` | некорректный ввод может дать 500 или утечку | fuzz-набор строк, проверка кода ответа и целостности базы |
| R3 | текст магазинов, товаров, вопросов ИИ, описаний | XSS при показе в админке и на веб-страницах | инъекции в данные, проверка экранирования в админке через браузер |
| R4 | заголовки ответов | отсутствуют заголовки защиты браузера | проверка заголовков |
| R5 | значения по умолчанию в `config.py` (`billing_pepper` «dev-only-change-me», CORS на localhost) | риск ошибки конфигурации в продакшене | проверка и предупреждение при запуске |
| R6 | отправка писем | письма не уходят наружу, код существует только в outbox | проверка, что код не попадает в ответы и журнал |
| R7 | TOTP 2FA | секрет хранится в открытом виде в базе; код можно повторить в окне 90 с | проверка повтора кода, зафиксировать как риск |
| R8 | лимиты (ratelimit) | в памяти процесса, сбрасываются при перезапуске | проверка лимитов кода и выгрузок |
| R9 | ошибки сервера | возможна утечка трассировки | вызов с неверными данными, проверка тела 500 |
| R10 | производительность | сборка выручки по всем заказам на каждый запрос | замер времени на большом объёме |

## 4. План тестирования по этапам

1. **Функциональные тесты сервера (pytest).** Дополнить тесты по каждому разделу списка; ожидаемые значения — из ТЗ, не из кода.
2. **Безопасность (pytest + Playwright).** Тесты R1–R9. Внешние сервисы не трогаем.
3. **Браузер (Playwright).** Страницы `/privacy`, `/terms`, `/delete-account`, `/admin` (вход, 2FA, все разделы). Веб-версия приложения: демо, обзор, товары, заказы, помощник, экран входа, подписка. Мобильный экран 390×844. Пустые поля, длинный текст, повторные нажатия, обновление страницы во время операции, попытка открыть чужой магазин.
4. **Нагрузка.** Локально, на тестовом сервере с несколькими десятками одновременных запросов. Замер p50, p95, ошибок. Большой объём данных — тестовая база на несколько тысяч записей.
5. **Исправления.** Для каждого провала: причина, критичность, исправление, повторный прогон упавшего теста, полный прогон.
6. **Отчёт.** Markdown и PDF. Для провалов — шаги воспроизведения и доказательства (скриншоты, логи).

## 5. Ограничения, которые надо честно указать в отчёте

- Apple и Google: проверка токенов с реальными ключами невозможна без аккаунтов владельца. Тестируется логика проверки на тестовых ключах.
- Мобильная сборка: проверяется веб-версия в браузере. Нативные сборки на телефоне не тестируются, это на владельце (задача 31).
- Почта: реальной отправки нет, коды берутся из outbox.
- Kaspi не подключён: все заказы — тестовые.
- Нагрузочные цифры — с локальной машины, не с сервера в Казахстане.
