# Отчёт QA: Satti Seller

Дата: 21.11.2026. Ветка: `feature/bootstrap`. Объект: сервер FastAPI, веб-версия приложения (Expo web), админ-панель, публичные страницы.

**Главный вывод.** Демо-режим в веб-версии работает: вход в демо, обзор, вкладки, поиск и фильтрация, экран входа. Перед тестом найден и исправлен критичный дефект: экран входа падал целиком. Сервер прошёл 170 автоматических тестов, включая 26 тестов безопасности. Нагрузка на 20 одновременных пользователей прошла без ошибок, но задержка заметно растёт. **Оценка: готово к показу демо на тестовом сервере; не готово к публичному запуску** (см. раздел 8).

## 4. Результаты проверки безопасности

- **Права доступа:** тесты на 13 маршрутах с чужим магазином — все возвращают 403 или 404, данные чужого магазина не попадают в ответ. Запись в чужой магазин (комиссии, налог, расходы) отклоняется. Демо-магазин недоступен аккаунту. Админ-панель для обычного пользователя отвечает 404.
- **Ввод:** SQL-подобные строки и нулевой байт в параметрах (`period`, `status`, `q`, `cursor`, `sort`, `filter`) не вызывают 500 и не меняют базу. Запросы строятся через ORM, сырого SQL с пользовательским вводом в коде нет.
- **XSS:** строки с тегами сохраняются и отдаются как JSON-текст. В админ-панели все значения проходят экранирование (проверено кодом и браузерными проверками).
- **Токены:** пустой, неверный и чужой формат заголовка отклоняется с 401. После выхода токен перестаёт работать.
- **Ошибки:** на неверный JSON — 422 без трассировки; внутренние ошибки отдают общий ответ 500 с кодом и записываются в журнал групп ошибок без данных.
- **Лимиты:** код входа — не больше 5 запросов в час, после 5 неверных попыток — блокировка.
- **Заголовки и конфигурация:** см. B2 и B3.
- **Не проверялось:** внешние сервисы не трогались (как требовалось). Реальные ключи Apple и Google, почта, сервер в Казахстане — вне текущего теста.

## 5. Нагрузка

Инструмент: `server/scripts/load_check.py`, запуск на локальном тестовом сервере с временной базой. Каждый пользователь — отдельная демо-сессия (300 заказов за 90 дней), по 15 запросов к обзору, прибыли, товарам и заказам.

| Одновременных пользователей | Запросов | Пропускная способность, запр/с | p50, мс | p95, мс | max, мс | Ошибки |
|---|---|---|---|---|---|---|
| 1 | 15 | 29.1 | 22.4 | 86.2 | 101.3 | 0 |
| 10 | 150 | 16.9 | 594.1 | 735.5 | 785.5 | 0 |
| 20 | 300 | 19.9 | 999.2 | 1224.4 | 1387.7 | 0 |

**Вывод.** Отказов нет. Пропускная способность не растёт с числом пользователей: один процесс обрабатывает запросы последовательно, а каждый запрос пересчитывает весь магазин (O1). Большой объём данных (тысячи заказов) не проверялся: тестовые данные демо фиксированы, а генерировать их на сервере без необходимости не стали. Цифры получены на локальной машине, не на сервере в Казахстане.

## 6. Соответствие функций ТЗ, проверенное в этом прогоне

- **Расчёты:** золотой набор G001–G010 и R001–R004 проходит. Лесенка прибыли сходится: чистые продажи − себестоимость − комиссия − доставка − налог = прибыль по товарам. Совпадение KPI обзора с API по тиынам.
- **Фильтры и поиск:** поиск по несуществующему товару и по строке 600 символов не ломает экран. Фильтры и сортировка проверены в API-тестах.
- **Вкладки и навигация:** все пять вкладок открываются без ошибки загрузки на 390×844.
- **Обновление данных:** данные лежат на сервере, после перезагрузки страницы не теряются (проверено в API-тестах сохранения; в браузере не проверено отдельно).

## 7. Тестовые дефекты, исправленные в ходе работы

Эти ошибки были в тестах, не в приложении. Ожидания тестов не менялись; менялось то, как тест обращается к системе:

- сырой нулевой байт в URL заменён на закодированный, как делает браузер;
- проверка «токен не в HTML» искала слово `Bearer`, которое есть в скрипте страницы; теперь проверяется значение токена;
- ожидание загрузки разделов админ-панели добавлено явно (гонка);
- сценарий входа использовал страницу старого контекста и неверную подсказку поля;
- прямой переход на `/login` в свежей сессии не рендерит приложение; вход проверяется с приветствия.

## 8. Готовность

| Назначение | Оценка | Основание |
|---|---|---|
| Демо потенциальным клиентам на тестовом сервере | **Готово с оговорками** | Демо-вход, обзор, вкладки, поиск работают в веб-версии на телефонной ширине. Экран входа исправлен. Нужно перезапустить серверы с последним кодом и проверить на телефоне (задача 31) |
| Публичный запуск | **Не готово** | Открыты O1 (производительность), O3 (почта для кодов), O2 (секрет 2FA), плюс всё, что требует аккаунтов владельца: Apple и Google с реальными ключами, сервер в Казахстане, проверка покупок, сборки и чек-листы на телефонах, публикация |

**Что сделать до демонстрации клиентам:** перезапустить API и веб-версию с последним кодом; пройти на телефоне путь «приветствие → демо → обзор → товары → помощник»; не показывать вход по почте и экран оплаты как рабочие.

**Что сделать до запуска:** O1 (кэш или агрегаты), O2 (шифрование секрета 2FA), O3 (почтовый сервис), O4 (общие лимиты), проверка покупок, сборки на телефонах, юридический просмотр текстов.
