## 7. Самооценка
- **Временные решения:** проверка ответов помощника — набор ручных правил; ключевые слова иногда не находят верный ответ, поэтому есть отдельная ручная проверка. Учёт стоимости с кэшем исправлен только для живого помощника; у черновиков стоимость $0, потому что модель не вызывается.
- **Технический долг:** `test_ai_eval_live.py` большой и трудно читается; архивы регрессий лежат в `server/tests/ai_eval_live_runs/` (не в git). Скрипты проверки чисел в `docs/eval/` ссылаются на абсолютные пути и на временный дамп, который нужно выгружать заново.
- **Хрупкие места:** тесты экранов склада и согласия мокают хуки API; реальные ответы сервера могут отличаться. Сетевые сбои в живых прогонах требуют повтора (очистка в скриптах прогонов). Переменная `SATTI_AI_LIVE` в `server/.env` включает платные вызовы в локальной разработке.
- **Что сделал бы иначе:** сразу учитывать токены кэша в стоимости (первый учёт занижал стоимость, это стоило нескольких итераций); не делать склад до готовности сервера; экранные тесты писать сразу с `await` и ожиданием результата.
- **Что переделал бы для корректной работы:** вынести правила проверки ответов в отдельный модуль с общими тестами; хранить остатки как журнал событий (приход, продажа, возврат), а не пересчитывать по заказам.
