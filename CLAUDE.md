# CLAUDE.md — Satti Seller

Satti Seller — мобильное приложение (iPhone и Android, App Store и Google Play) для продавцов Kaspi: прибыль по каждому товару, заказы, недостающие данные и ИИ-помощник. Приложение — экраны; расчёты, данные и ИИ — на сервере.

## Документы

- `docs/overview.md` — коротко и простыми словами.
- `docs/spec.md` — функции, сервер и API, расчёты, импорт, ИИ, данные, требования магазинов, **план задач (раздел 16)**.
- `docs/design.md` — цвета, шрифт, компоненты, навигация, все экраны. Макеты — `docs/design/mockups/`.
- `docs/owner.md` — решения владельца. Ничего оттуда не реализуй без отдельного задания.
- `docs/adr/` — архитектурные решения.

Читай только разделы, нужные для текущей задачи.

## Как работать

1. Перед задачей прочитай этот файл, нужные разделы документов и код, который затрагиваешь. Проверь состояние git; чужие незакоммиченные изменения не трогай.
2. Делай ровно одну задачу из плана. Следующую — только по просьбе.
3. В начале коротко перечисли, что изменишь. В конце — что сделано, какие проверки запущены и их фактический результат, известные ограничения, как посмотреть результат на телефоне.
4. Команды запуска, сборки и проверок определи сам по состоянию проекта и держи актуальными в README.
5. После успешных проверок — коммит с понятным сообщением в рабочей ветке (не в main). Push рабочей ветки — после каждой задачи (spec-2.1, раздел 23).
6. Если нужен ответ владельца (Kaspi, юрист, цена, аккаунт магазина приложений) — остановись на заглушке или флаге и сформулируй точный вопрос. Не подставляй «типичные» значения.

## Стек

- Приложение: Expo (актуальный стабильный SDK), TypeScript strict, Expo Router, шрифт Inter, иконки Lucide. Библиотеки выбирай сам: совместимые с текущим Expo SDK, бесплатные, без рекламных и трекинговых SDK, без лишних разрешений.
- Сервер: Python 3.12+, FastAPI (или существующий Flask, если так решено в ADR-0002), SQLAlchemy 2, Alembic, PostgreSQL (локально допустим SQLite). OpenAPI → типизированный клиент для приложения.

## Жёсткие правила

### Данные и безопасность
- До этапа B — только синтетические данные. Никаких логинов, паролей, SMS-кодов Kaspi; никакого скрейпинга и неофициальных методов Kaspi.
- В приложении нет секретов. Ключи ИИ-сервиса, Kaspi и почты — только на сервере. Токены сессии — только в Keychain / Keystore.
- В логах, событиях аналитики, отчётах об ошибках и ИИ нет данных покупателей, токенов, кодов входа, содержимого файлов.
- Приложение ничего не меняет в Kaspi и ничего не отправляет покупателям.

### Деньги
- Считает только сервер. Приложение только форматирует.
- Деньги — целые тиыны; ставки и доли — целые базисные пункты. `float` для денег запрещён. Округление — половина вверх (ROUND_HALF_UP), комиссия — по строке.
- Неизвестная затрата — не ноль. Маржа считается по одному набору товаров; покрытие показывается всегда.
- Golden-тесты G001–G008 и R001–R003 (`docs/spec.md`, раздел 6.6) всегда проходят.

### Время
- В БД — UTC с часовым поясом. Периоды — в часовом поясе магазина (по умолчанию Asia/Almaty, UTC+5). Текущее время — через подменяемые в тестах часы.

### ИИ
- Только после согласия пользователя внутри приложения.
- Только read-only инструменты, не больше 3 вызовов. Модель пишет шаблон без цифр; числа, даты и названия товаров подставляет сервер. `evidence`, `missingData`, `confidence` формирует сервер.
- У каждого ответа и черновика — оценка и «Пожаловаться». По умолчанию — mock; живая модель на реальных данных — только после решения владельца.

### Дизайн
- Цвета, шрифты, отступы, радиусы — только через токены темы из `docs/design.md`. Никаких значений, вписанных прямо в компоненты.
- Обе темы, русский и казахский, крупный системный шрифт, подписи для VoiceOver и TalkBack, зоны нажатия не меньше 44 pt.
- Все тексты — в файлах локализации. Казахские тексты помечай для проверки носителем языка.
- Только iPhone и Android-телефоны, только портрет.

### Магазины приложений
- Соблюдай `docs/spec.md`, раздел 12: удаление аккаунта в приложении, согласие на ИИ, жалоба на ответ ИИ, разрешения только по необходимости и в момент действия, без товарного знака Kaspi в названии, иконке и метаданных.

## Режим работы до запуска
Главный документ — docs/MASTER_PLAN.md.
При команде «продолжаем» или «продолжай», в начале новой сессии и после сжатия контекста:
прочитай docs/HANDOFF.md, затем docs/MASTER_PLAN.md (разделы 2–4, 6, 8 и текущий этап раздела 5)
и выполняй «Начало сессии» из раздела 2.

Уведомления на телефон: когда заканчиваешь этап, упираешься в блокировку или лимит, или тебе нужен ответ владельца — отправь владельцу push-уведомление на телефон (Remote Control / push, см. настройки пользователя).


## Работа с координатором

- Координатор (Claude в приложении владельца) пишет указания в docs/INBOX.md; выполняй по номерам (К-0, К-1, К-2…), новые — в конец файла.
- Статус и отчёт — в docs/REPORT.md (шаблон: СТАТУС, Обновлено, Сейчас делаю, Сделано (коммиты), Тесты, Указания К-…, Проблемы, Вопросы владельцу, Риски). Прежний отчёт переноси в начало docs/REPORT_LOG.md.
- Не жди «продолжаем»: после пункта сразу бери следующий. Проблему не решил за 2 попытки — в REPORT.md, раздел «Проблемы», и бери другой пункт.
- Коммит после каждого пункта; push ветки без force после крупных шагов; в конце — git bundle в C:\Users\user\Desktop\satti-backups\.
- Всё ждёт владельца — последняя строка ответа «СТАТУС: ЖДУ ВЛАДЕЛЬЦА». Всё возможное сделано — «СТАТУС: ГОТОВО».
- Повторяющаяся задача каждые 10 минут: прочитать docs/INBOX.md (в новой сессии создавать заново). Если размер файла не изменился с прошлой проверки — не перечитывать целиком.
- Читать только docs/INBOX.md. Выполненные указания лежат в docs/INBOX_ARCHIVE.md — только для справки, заново их не выполнять (так меньше расходуется лимит).
